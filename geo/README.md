# /geo — satellite processing (Google Earth Engine)

These scripts turn satellite data into the small static files the app uses. Outputs are
**committed** to `public/data/`, so the demo never depends on Earth Engine being reachable.

| Script | Input | Output (`public/data/`) |
|---|---|---|
| `imerg.py` | NASA GPM IMERG V07 half-hourly rain | `imerg_2022_zones.json` — mm per 3 h per zone |
| `sentinel1_flood.py` | Sentinel-1 GRD VV, JRC GSW, Copernicus GLO-30 | `flood_extent_2022.geojson` — flood MultiPolygon |
| `dem_risk.py` | Copernicus GLO-30 + the flood image | `zone_base_risk.json` — `base_risk_score` per zone |

> **The committed files are currently SYNTHETIC** (`"synthetic": true`), generated by
> `npm run data:synthetic` from the hand-drawn zones, so the demo works without an Earth
> Engine account. They have the same schema. Run the scripts below to replace them with
> real satellite-derived data. The dashboard labels synthetic data.

## Run

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r geo/requirements.txt
earthengine authenticate                       # once
export EE_PROJECT=your-ee-cloud-project        # registered for noncommercial Earth Engine

npm run data:synthetic                         # writes public/data/zones.geojson (input for the scripts)
python geo/imerg.py                            # rainfall Sept–Oct 2022
python geo/sentinel1_flood.py                  # 2022 flood extent
python geo/dem_risk.py                         # base risk per zone (uses the flood image)
npm run db:seed                                # load the new files into the database
```

Note that `npm run data:synthetic` regenerates *all* synthetic files — run it **before** the
Earth Engine scripts (it only exists to produce `zones.geojson` and stand-ins).

## Methods (short)

- **Rainfall:** sum of half-hourly IMERG precipitation rate × 0.5 h in each 3 h window,
  averaged over each zone polygon. IMERG pixels are 0.1° (~11 km), larger than the zones.
- **Flood extent:** median VV backscatter for the dry season (Jan–Mar 2022) vs. the flood
  window (5–20 Oct 2022); flooded where it dropped > 3 dB **and** is below −15 dB; minus
  permanent water (JRC seasonality ≥ 10 months) and slopes ≥ 5°; specks < 8 px removed.
- **Base risk:** `0.4·(1 − elevation_norm) + 0.2·(1 − slope_norm) + 0.4·flood_overlap_2022`.

These are deliberately simple and explainable; thresholds are constants at the top of
`sentinel1_flood.py`.
